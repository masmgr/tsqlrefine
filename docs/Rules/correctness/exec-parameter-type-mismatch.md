# exec-parameter-type-mismatch

## Summary

Reports an `EXEC` argument when its statically known type may lose information while being
assigned to the resolved procedure parameter.

## Examples

```sql
DECLARE @id bigint = 2147483648;
EXEC dbo.TakeInt @id; -- bigint to int may overflow

EXEC dbo.TakeCode 'too-long'; -- warns when @code is varchar(4)
```

The rule infers literal, declared-variable, `CAST`, and `CONVERT` types. It checks numeric and
datetime precedence through `TypeCompatibility`, along with known string lengths and Unicode to
ANSI conversion. Expressions whose type cannot be determined are skipped to avoid speculation, but
a string argument with an unknown character length (for example `varchar(max)` or an unresolvable
expression) is still reported against a fixed-length parameter, since truncation cannot be ruled
out. The rule requires an object catalog generated by `schema collect-objects`.

## Category

Correctness

## Severity

Warning

## Fixable

No
